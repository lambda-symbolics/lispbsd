* Sources of truth

=lisp-machine-spec.org= is the normative design.  =AGENTS.md= is repository
policy.  Tracked source plus the =lispbsd= test suite are executable truth.

* Runtime boundaries

The running system has five components with explicit interfaces:

- NetBSD kernel and drivers, built from the reference source tree with
  =script/netbsd-build= and exercised under QEMU with =script/vm-run=.
- SBCL as the Common Lisp runtime substrate, reached only through the
  =runtime= protocol in =src/runtime.lisp= and =src/runtime-sbcl.lisp=.
- The live Lisp world: =world=, =activity=, =resource=, =event=, =authority=,
  and =generation= objects in the =lispbsd= package.
- The window system and UI backend: a canonical 1-bit logical framebuffer
  in =src/bitmap.lisp=; windows, fonts, and display backends follow.
- An optional resident agent, not yet present; Autolith may later implement
  the agent protocol through an adapter.

* Hosted prototype

Phase 0 runs inside an ordinary SBCL process.  =make-hosted-world= constructs
an operational world, probes host machine resources, and grants the world
root authority.  It does not boot NetBSD and does not start a display.

* Native boot so far

The development disk is a NetBSD 10.1 live image booted with the LISPBSD
kernel.  pkgsrc SBCL 2.6.5 is installed on that disk.  Root login on
=constty= execs SBCL, which loads =/lispbsd/boot.lisp= and starts an
operational world.  =script/guest '(lispbsd:world-phase lispbsd:*world*)'
returns =:OPERATIONAL=.  Unix daemons still exist on the live image; they
are not the user-visible operating environment.

The LISPBSD kernel includes =vio9p=.  QEMU can export a host directory with
=VIRTFS=; the guest creates =/dev/vio9p0= (char 356) and mounts it with
=mount_9p -cu=.  Autolith source is reachable that way.  Compiling Autolith
inside the guest is still unfinished: its Quicklisp and sibling checkouts
are large, and the first load over 9p is slow.
